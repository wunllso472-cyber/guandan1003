# 全屏笔记体验建议

用户浏览全屏笔记时，会先看到小工具的预览，再点进来使用。推荐让用户在预览里就能看懂工具的用途，进入后能直接找到主要操作。

## 如何引导

需求涉及全屏笔记时，主动挑一两项与当前工具最相关的做法，向作者说明用户会看到什么、操作起来有什么好处。例如，可以向照片工具的作者建议：“首屏放一张标明‘示例’的处理效果图，旁边放‘选择照片’按钮。读者看预览就知道能做出什么效果，点进来就能选自己的照片。”

按作者选定的方向实施，沿用工具已有的功能和视觉风格。作者已明确想优化的部分可直接动手。涉及新增页面或改变操作流程时，先说明取舍，让作者决定。

## 按工具用途选择做法

| 关注点 | 建议 | 适用示例 |
| --- | --- | --- |
| 预览容易理解 | 可把用途、代表性内容或效果放在首屏，让用户知道点进去能做什么；需要示例时明确标注 | 照片工具展示代表性效果，计算器展示输入区与用途 |
| 核心操作容易找到 | 可让进入后的主要操作直接可见；额外的开始步骤按业务需要设置 | 抽签按钮、选图入口、计算按钮 |
| 内容长度自然 | 单屏工具关注操作区可达，长内容关注正文延续与滚动；按实际容器空间安排内容 | 游戏主场景、长清单、攻略 |
| 进入前后连贯 | 可观察预览与进入后的主体位置、大小和内容是否容易对应，减少突兀跳位 | 图片主体、卡片、标题区域 |

9:15 可作为全屏笔记预览的一个观察尺寸。页面比例和内容长度由工具用途与实际容器决定，无需为此统一成固定比例或压缩成一屏。

## 与容器配合

笔记预览热区、进入 / 退出动画和容器准入授权由宿主提供；H5 负责工具内容与业务交互。优化体验时遵循[小工具在线文档](https://miniapp-sandbox.xiaohongshu.com/minitool/doc)公开的契约，不在页面里模拟这套宿主界面与流程。

- 顶部有标题或操作按钮时，在小工具在线文档中搜索 `getWindowInfo`，按文档说明判断当前客户端是否支持。支持时，读取容器尺寸、安全区和可见宿主按钮的位置。若标题或操作与宿主按钮重叠，可调整标题留白，或把操作移到下一行。
- 预览与详情的尺寸映射、截图时机、页面实例及生命周期以宿主公开契约为准。视觉连续性作为体验观察目标，不据此自造预览模式、宿主消息或过渡实现。
- 需要拍照、录音等能力时，让相关操作入口表达清楚用途，并按公开契约处理授权与取消，帮助用户理解下一步会发生什么。

## 观察优化效果

采用相关建议后，可在支持全屏笔记场景的平台与真机上观察：预览能否表达用途，进入后是否容易找到主操作，主体是否连贯，内容与操作是否被遮挡，以及长内容是否易于浏览。

向作者说明实际观察到的效果，待真机验证的体验点单独标明。构建、打包和发布按主 Skill 的通用规范执行。
